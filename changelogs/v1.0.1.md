# Changelog — v1.0.1 (Backend Foundation & Architecture Setup)

**Release Date:** 2026-08-27  
**Version:** `1.0.1`  
**Status:** Completed & Deployed  

---

## Summary of Changes

This release establishes the foundational infrastructure, runtime configuration, build pipeline, database integration, architectural standards, and automated workflows for the **Healthcare ERP Backend**.

---

## Completed Tasks

### 1. Project Initialization & Runtime
- **Initialize Bun Project**: Configured the project on [Bun](https://bun.sh) runtime with native TypeScript execution and high-performance server capabilities.
- **Dependency Management**: Integrated core dependencies (`hono`, `@prisma/client`, `zod`) and development dependencies (`prisma`, `@types/bun`).

### 2. TypeScript & Path Aliasing
- **Configure TypeScript**: Configured `tsconfig.json` with modern `bundler` module resolution, strict type checking (`strict`, `noUnusedLocals`, `noUnusedParameters`, `noFallthroughCasesInSwitch`), and JSX support.
- **Path Aliasing**: Established clean `@/*` import paths mapped to `./src/*` across the entire codebase.

### 3. Hono Framework & Server Setup
- **Configure Hono**: Initialized the core Hono application entry point with modular routing.
- **Essential Middlewares**:
  - `logger()`: Real-time request and response logging.
  - `cors()`: Configurable Cross-Origin Resource Sharing based on environment configuration.
  - `secureHeaders()`: Security headers following OWASP recommendations.
  - `prettyJSON()`: Pretty JSON response formatting.
- **Centralized Error Handling**: Integrated `errorHandler` (handling `HTTPException` and sanitizing production errors) and `notFoundHandler` for structured 404 responses.
- **Health Check Route**: Implemented `GET /health` with system status and live database connectivity latency tracking.

### 4. Database & Prisma ORM
- **Configure Prisma**: Setup `prisma/schema.prisma` configured for PostgreSQL datasource and `prisma-client-js` generator.
- **Data Models**: Created baseline models: `User`, `Role` enum (clinical and operational roles), `UserStatus` enum, and `AuditLog`.
- **Prisma Client Singleton**: Created `src/db/prisma.ts` attached to `globalThis` during development to prevent connection exhaustion during hot reload.
- **Database Scripts**: Added `db:generate`, `db:migrate`, `db:push`, `db:studio`, and `db:validate` in `package.json`.

### 5. Environment Variables & Validation
- **Configure Environment Variables**: Created `.env` and `.env.example` templates covering `NODE_ENV`, `PORT`, `DATABASE_URL`, `JWT_SECRET`, `JWT_EXPIRES_IN`, `CORS_ORIGIN`, and `LOG_LEVEL`.
- **Create .env Structure**: Standardized environment schema for local development and deployment.
- **Create Environment Validation**: Built `src/config/env.ts` with **Zod** to validate environment variables on startup and exit immediately if required variables are missing.
- **Secrets Protection**: Configured `.gitignore` to prevent leaking `.env` files and build outputs.

### 6. Development & Production Environments
- **Configure Development Environment**: Configured `bun run dev` with `--hot` auto-reloading for rapid development.
- **Configure Production Environment**: Configured production bundling using `bun build src/index.ts --outdir dist --target bun --sourcemap` producing optimized artifacts in `./dist`.
- **Configure Scripts for Development**: Added `clean`, `dev`, and `typecheck` commands.
- **Configure Scripts for Builds**: Added `build`, `build:bundle`, and `start` (`bun run dist/index.js`) commands.

### 7. Database Seeding Script
- **Configure Scripts for Database Seeding**: Created `prisma/seed.ts` providing idempotent seed accounts for all system roles (`SUPER_ADMIN`, `ADMIN`, `DOCTOR`, `NURSE`, `PHARMACIST`, `RECEPTIONIST`, `LAB_TECHNICIAN`, `ACCOUNTANT`) with bcrypt-hashed passwords and initial audit log entries.
- **Prisma Seed Config**: Registered seed script under `"prisma": { "seed": "bun run prisma/seed.ts" }` and `bun run db:seed`.

### 8. Automation & Helper Scripts
- **Master Runners**: Created zero-configuration interactive runner scripts:
  - `run.sh` (macOS / Linux)
  - `run.bat` (Windows)
  - Featuring pre-flight checks: Bun installation verification, auto-creation of `.env` from `.env.example`, and auto-installation of dependencies.
- **Standalone Scripts**: Added dedicated scripts under `scripts/`:
  - `scripts/dev.sh` & `scripts/dev.bat`
  - `scripts/build.sh` & `scripts/build.bat`
  - `scripts/start.sh` & `scripts/start.bat`
  - `scripts/test.sh` & `scripts/test.bat`
  - `scripts/db.sh` & `scripts/db.bat`

### 9. Source Code & Naming Conventions
- **Establish Source-Code Conventions**: Recorded full standards in [docs/CONVENTIONS.md](../docs/CONVENTIONS.md).
- **Establish Naming Conventions**: Standardized `kebab-case` file naming with role suffixes (`*.route.ts`, `*.controller.ts`, `*.service.ts`, `*.repository.ts`, `*.dto.ts`, `*.test.ts`), `camelCase` functions/variables, `PascalCase` types/classes/enums, and `SCREAMING_SNAKE_CASE` constants.
- **Establish Module Naming Conventions**: Defined **Modular-Monolith** domain module layout (`src/modules/<domain>/`) with 4-tier layer isolation (**API / Controller**, **Application Service**, **Repository**, **DTO**). Recorded architecture and request lifecycle in [docs/ARCHITECTURE.md](../docs/ARCHITECTURE.md).

### 10. Reference Domain Implementation & Tests
- **Users Domain Module**: Built `src/modules/users/` showcasing the complete 4-tier architecture (`user.dto.ts`, `user.repository.ts`, `user.service.ts`, `user.controller.ts`, `user.route.ts`).
- **Audit Log Decoupling**: Implemented `src/modules/audit-logs/audit-log.repository.ts` with dependency injection.
- **Automated Test Suite**: Added comprehensive in-memory unit tests and HTTP integration tests (`tests/app.test.ts`, `src/modules/users/user.test.ts`) with 100% pass rate.
