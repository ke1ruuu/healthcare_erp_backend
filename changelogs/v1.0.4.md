## Summary of Changes

Version **v1.0.4** introduces comprehensive PostgreSQL database persistence, schema governance, migration workflows, 100-record seed data generators, transaction conventions, and major UI enhancements to the React Vite monitoring dashboard.

## Detailed Changelog

### 1. PostgreSQL Database Configuration & Diagnostics
- **Live PostgreSQL Engine Integration**: Connected to local PostgreSQL 18 with persistent schema mapping and hot-reload safe singleton pool (`src/db/prisma.ts`).
- **Database Setup & Pre-Flight Tooling**: Implemented `scripts/setup-db.ts` (`bun run db:setup`) performing TCP connectivity probing, live query latency measurement via `SELECT 1`, and automated migration synchronization.
- **Docker Support**: Added `docker-compose.yml` for containerized PostgreSQL provisioning with health check probes.

### 2. Identifiers, Timestamps & Status Conventions
- **Common Identifiers**: Standardized UUID v4 primary keys (`id String @id @default(uuid())`) across models and formatted Medical Record Numbers (`MRN-YYYYMMDD-XXXX`) for patients.
- **Timestamp Lifecycle**: Enforced UTC timestamp conventions across all models (`createdAt DateTime @default(now())`, `updatedAt DateTime @updatedAt`, `deletedAt DateTime?`).
- **Status Lifecycle Enums**: Added `UserStatus` (`ACTIVE`, `INACTIVE`, `SUSPENDED`) and `PatientStatus` (`ACTIVE`, `INACTIVE`, `DECEASED`, `TRANSFERRED`) enums with dedicated index coverage.

### 3. Database Constraints, Soft-Delete Strategy & Indexing Conventions
- **Foreign-Key Constraints & Referential Actions**:
  - `SetNull`: Applied to `AuditLog.userId` referencing `User.id` (`onDelete: SetNull`), preserving immutable forensic audit records even if staff accounts are removed.
  - `Restrict` / `NoAction`: Standard policy for clinical dependencies (preventing deletion of patients with active medical records).
  - `Cascade`: Restricted strictly to composite child line-items.
- **Soft-Delete Strategy & Retention Lifecycle**:
  - Prohibited physical `DELETE` on clinical tables in compliance with HIPAA §164.312 and GDPR Article 17.
  - Enforced `where: { deletedAt: null }` across all repository reads, queries, and listings.
  - Emitted `action: "DELETE_<ENTITY>"` audit entries and domain events on soft-deletion.
- **Indexing Conventions & Optimization**:
  - Mandatory B-Tree indexes on all foreign key columns (`@@index([userId])`).
  - Lifecycle indexes on `@@index([deletedAt])` and `@@index([status])`.
  - Composite lookup indexes on `@@index([firstName, lastName])`, `@@index([entity, entityId])`, and `@@index([createdAt])`.
- **Unique Constraints & Business Keys**:
  - Enforced permanent uniqueness across active and soft-deleted states for `email` on `User` and `medicalRecordNumber` on `Patient`.
  - Automatic conversion of Prisma `P2002` violations into standard `409 Conflict` (`DUPLICATE_RESOURCE`) responses.

### 4. Database Migration Workflow & Initial Migration
- **Prisma Migration Engine**: Transitioned from schema push to audited, versioned SQL migrations in `prisma/migrations/`.
- **Initial Migration**: Generated `20260828000000_init_healthcare_erp_schema/migration.sql` covering all enums, tables (`users`, `patients`, `audit_logs`), foreign keys, unique keys, and indexes.
- **Standardized Migration Commands**:
  - `bun run db:migrate`: Interactive development migration generator (`prisma migrate dev`).
  - `bun run db:migrate:deploy`: Non-interactive production/CI migration applier (`prisma migrate deploy`).
  - `bun run db:migrate:status`: Schema drift and migration history verification.
  - `bun run db:migrate:reset`: Clean database wipe, re-migration, and seed execution.
- **Architecture Documentation**: Authored `docs/DATABASE_MIGRATIONS.md` covering zero-downtime expand-contract schema evolution.

### 5. Development & Test Seed Data (100 Records/Table)
- **High-Volume Seed Generator (`prisma/seed.ts`)**:
  - **108 Users**: Staff accounts distributed across all 8 roles (`SUPER_ADMIN`, `ADMIN`, `DOCTOR`, `NURSE`, `PHARMACIST`, `RECEPTIONIST`, `LAB_TECHNICIAN`, `ACCOUNTANT`) with Bcrypt password hashing (`Password@123`).
  - **106 Patients**: Realistic patient records with unique MRNs, birth dates (ages 18-85), blood types, genders, full street addresses, and emergency contacts.
  - **100 Audit Logs**: Structured forensic audit entries linking real staff and patient IDs with realistic JSON metadata, IP addresses, and user agents.
- **Idempotency**: Implemented safe upsert/count logic allowing repeated execution without data corruption.

### 6. Database Transaction Conventions & Atomicity
- **Standardized Transaction Patterns (Section 5.9)**:
  - Interactive Transactions (`prisma.$transaction(async (tx) => ...)`): Standard for multi-table atomic operations (e.g. creating patient + audit log entry).
  - Sequential Batch Transactions (`prisma.$transaction([...])`): Standard for bulk operations.
  - Configured timeouts (`maxWait: 5000ms`, `timeout: 10000ms`) and isolation levels (`ReadCommitted` default, `Serializable` for financial ledgers).
  - Automatic rollback on unhandled exceptions and strict prohibitions on external network calls within transaction closures.

### 7. Automated Sequential Launch Scripts & Process Conflict Remediation
- **One-Command Automated Launcher (`launch.sh` / `launch.bat` / `bun run launch`)**:
  - Non-interactively executes the 6-phase pipeline: runtime verification, `.env` initialization, dependency check, database setup & migration, architecture & drift checks, and service startup.
- **Active Process Conflict Detection**: Automatically detects and terminates lingering processes on ports `3000` (Backend API) and `5173` (React Dashboard) before startup.

### 8. Backend Monitoring Dashboard UI Improvements (React + Vite)
- **High-Density Command Deck Design System**:
  - Modernized `dashboard/` with dark ground (`#0B0E14`), electric indigo accents, and functional status indicators.
  - Sectional navigation: Overview (Service Vitals & Dual-Trace Canvas Chart), Master Records (Users & Patients tabular data), Audit Trail (Forensic log viewer), API Probe (Interactive endpoint console), and System (Architectural boundary enforcement guard).
  - Resilient polling with selectable sampling intervals (`2s`, `3s`, `5s`, `10s`, `Hold`) and instantaneous manual sampling.
